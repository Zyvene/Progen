This file exists so that source code (.py and .gd files) can stay free of comments and docstrings.   PART 1 -- Installation and run guide
  PART 2 -- Comment/docstring catalogue

================================================================================
PART 1 - INSTALLATION AND RUN GUIDE
================================================================================

Requirements
------------
- Windows, with Python 3.12.10 installed and available as `py -3.12`.
- Godot 4.4.1 (for the front-end / UI / 3D viewport).

1. Create and activate a virtual environment (PowerShell or VSCode)
-----------------------------------------------------------
> py -3.12 -m venv .venv-1
> .venv-1\Scripts\Activate.ps1

If PowerShell blocks the activation script, activate without changing execution policy by calling the venv's Python directly instead (see step 4).

2. Install Python dependencies
-------------------------------
> pip install -r requirements.txt

3. Run the developer smoke tests
----------------------------------
> python demo.py
> python test_building.py
> python inspect_model.py

- `demo.py` builds a small spread of sample buildings from
  regular_buildings.xlsx (or a single built-in fallback topology if that
  file is missing), validates each one, and runs a linear static gravity
  check as a cheap "is this model actually analysis-ready" smoke test.
- `test_building.py` builds one large topology and prints a validation
  report.
- `inspect_model.py` builds one topology and prints real node coordinates,
  element connectivity, material properties, applied loads, a validation
  report, and the result of an actual gravity analysis -- useful for
  confirming the OpenSeesPy model looks the way it should.

4. Run one full NLTHA (nonlinear time-history analysis) from the CLI
------------------------------------------------------------------------
> python simulation.py --topology sample_topology.json --output results.json --history nltha_history.csv

If activation in step 1 was blocked, call the venv's Python directly instead
of `python`:
    .\.venv-1\Scripts\python.exe -m pip install -r requirements.txt
    .\.venv-1\Scripts\python.exe demo.py
    .\.venv-1\Scripts\python.exe simulation.py --topology sample_topology.json --output results.json --history nltha_history.csv

Useful `simulation.py` flags:
    --topology  path to a JSON file following SCHEMA.md (defaults to a
                small built-in topology if omitted)
    --motion    a CSV file with `time,acceleration_g` rows (or one
                acceleration-g value per row); applied identically to both
                the X and Y excitation directions
    --magnitude seismic magnitude, 1-10 (default 5.0); ignored if --motion
                is given
    --dt        analysis time step in seconds (default 0.01)
    --duration  strong-shaking duration D5-95 in seconds (default 15.0);
                the full record is about 1.7 x longer
    --output    where to write the results JSON
    --history   where to write the full per-step time-history CSV

Output files (wherever --output / --history point):
    results.json        fundamental period, NSCP drift limit, peak stress,
                         peak displacement (X and Y), peak deformation,
                         maximum story drift, maximum IDR, the full
                         Performance Evaluation result (with triggered rules
                         and demand ratios), the model state, and the overall
                         PASS/FAIL verdict.
    nltha_history.csv    one row per converged time step: time_s,
                         stress_mpa, displacement_m, displacement_y_m,
                         deformation_m, idr.

5. Run the Godot front end
-----------------------------
- Open the `godot_ui/` folder as a project in the Godot 4.4.1 editor and run
  the main scene.
- `GENERATE STRUCTURE` builds and displays the frame from the sidebar inputs,
  with every member drawn as a W12X26 I-profile at true size.
- The rule dropdown shows visual mock-ups of each Table 1 action (W-shape
  upsizing, X-bracing, mid-height struts); no analysis is run for previews.
- `RUN SIMULATION` creates `runs/run_<date-time>/`, writes `input.json`
  there, and launches `simulation.py --run-dir` (from `.venv-1`) as a
  background subprocess that runs the closed loop automatically:
  Iteration 0 -> feedback -> Iteration 1 ... (up to 10 feedback
  iterations). Each finished iteration appears in the Iteration Records
  panel with its results printed in the terminal; click an entry to view
  that iteration again.
- While an iteration is simulating, the main viewport shakes the structure
  with the displacements OpenSeesPy is computing (magnified; factor shown
  bottom-left). The shake ends when that iteration is saved.
- After the run, the Simulation Preview box shows the selected iteration's
  structure; click it to replay that iteration's recorded shake in both the
  preview and the main viewport
  (iteration_<n>/frames.json) in real time.
- A member falls to the ground at the moment its strain first exceeds the
  rupture strain (display only; the analysis keeps the member). Columns
  keep their length, so during a collapse the building sways and sinks.
  A collapsed iteration's playback ends on the last computed frame with
  the collapse time shown.
- `Clean Previous Runs` permanently deletes every `runs/run_*` folder after
  a confirmation dialog; it is disabled while a simulation is running.
- `RESET STRUCTURE` clears the viewport and terminal.

"""
procedural_content_generation.py
=================================
Procedural Content Generation layer: constructs the beam-column structural
topology from validated parametric inputs using deterministic rule-based
assembly, where every grid intersection across all floor levels becomes a
connection point for beams and columns.

This is pure geometry -- no OpenSeesPy import, no node tags, no material or

Node key: (level, row, col), where level 0 = base/ground and

- Columns: one per grid point per story, connecting

  (the base) has no beams, only columns rising from it.

Explanation: Establishes this file as the thesis's dedicated "Procedural

"""
seismic_simulation.py
======================
Seismic Simulation layer: translates a Procedural Content Generation
topology into an analysis-ready OpenSeesPy model (nodes, base fixity,
material, fiber sections, beam-column elements, gravity loads), then
executes Nonlinear Time-History Analysis (NLTHA) against a bidirectional
base excitation.

Units are kN, m, seconds throughout. Ground acceleration input is in g
unless a caller passes acceleration in m/s^2 directly to `run_nltha`.

Model conventions
------------------
- ndm=3, ndf=6 (full 3D frame, 6 DOF/node)
- Axes: X, Y = plan directions (matches bay_count_x / bay_count_y),
        Z = vertical (story direction)
- Node tag scheme: unique per (level, row, col):
      tag = level * (n_nodes_x * n_nodes_y) + row * n_nodes_x + col + 1
- Base nodes (level 0) are fully fixed (fix 1 1 1 1 1 1) -- a simple
  fixed-base idealization; swap for a spring/foundation model later if
  the project needs one.

Load path assumption (panel loads -> beam loads): the floor/roof deck is
assumed to span in the Y direction onto the X-direction beams (a one-way
slab), which is the standard simplifying assumption used before a real
slab/deck model exists. Only X-direction beams receive tributary panel
load; Y-direction beams carry no directly-applied panel load in this pass.
"""
Explanation: Module docstring identifying this file as the thesis's
"Seismic Simulation" layer -- the box that takes PCG's pure topology and
turns it into a real OpenSeesPy model, then runs the NLTHA. Documents the
unit system (kN, m, s), the 3D model conventions (6 DOF/node, axis
meanings, node tag formula, fixed-base idealization), and explicitly
flags the one-way load-path simplification (only X-direction beams get
panel load) as a documented modeling choice rather than an oversight.

[seismic_simulation.py : 58-80] *** KEY CITATION -- PRESERVE EXACTLY ***
    # --- Magnitude -> PGA ---------------------------------------------------
    # The paper defines the seismic magnitude input as a 1-10 logarithmic scale
    # (Michigan Tech, 2021) but does not specify a magnitude-to-acceleration
    # conversion. This uses the Esteva & Villaverde (1973) attenuation
    # relationship, evaluated at a fixed nominal epicentral distance since this
    # tool has no distance input at all -- consistent with the thesis's own
    # disclaimed limitation that "the structural evaluations do not account for
    # the structure's proximity to the epicenter or hypocenter" (Scope and
    # Limitation of the Study).
    #
    # PGA [cm/s^2] = b1 * exp(b2*M) / (R + b4)^b3, with b1=5600, b2=0.8, b3=2,
    # b4=40 (fit on firm/rock-site strong-motion records).
    #
    # Esteva, L., & Villaverde, R. (1973). Seismic risk, design spectra and
    # structural reliability. In Proceedings of the Fifth World Conference on
    # Earthquake Engineering (Vol. 2, pp. 2586-2596). Rome, Italy: Italian
    # Association for Earthquake Engineering.
    # No DOI: this conference proceedings predates the DOI system (introduced
    # in 2000) and none has been retroactively assigned -- verified by search;
    # not omitted for convenience. Coefficients cross-checked against the JCSS
    # Probabilistic Model Code, Section 2.17 "Earthquake Loads" (Joint
    # Committee on Structural Safety), which reproduces the same relationship:
    # https://www.jcss-lc.org/publications/jcsspmc/earthquake1b.pdf
Explanation: This is the thesis-fidelity citation for the single most
scrutinized piece of engineering judgment in the whole tool: how a 1-10
seismic magnitude input (which the thesis defines but never converts to a
physical ground-motion amplitude) becomes an actual peak ground
acceleration. The paper leaves this conversion completely unspecified,
so this uses the Esteva & Villaverde (1973) magnitude-attenuation
relationship, a real, citable formula from a peer-reviewed earthquake
engineering proceedings, evaluated at one fixed nominal distance because
this tool (matching the thesis's own stated limitation) has no
epicenter-distance input at all. The formula and its coefficients
(b1=5600, b2=0.8, b3=2, b4=40) were independently verified via multiple
web searches and cross-checked against the JCSS Probabilistic Model Code
(a structural-safety reference document) before being adopted, and the
comment explicitly documents that no DOI exists for this 1973 proceedings
(it predates the DOI system entirely) rather than silently omitting a
citation.
